# 环境知识与当前任务分离

日期：2026-11-05（北京时间）。用户明确：记忆让机器人熟悉环境，例如知道某个方向通向什么；每个episode根据自己的目标重新决定路线。

后续实现：可选的真实视觉分支生成、逐分支预测查询与当前任务规划器已接入，见 [预测查询接入记录](world_model_predictive_harness_20261105.md)。下文“未实现”和62项测试描述的是此前接口修正时的状态，不代表后续接入实验的结论。

## 设计约束

环境记忆回答：在过去哪个观察、哪个实际方向和执行条件下，到达后见到了什么，哪些连接实际走通过，哪些证据未知或失效。旧任务指令可以作为原始经历的审计信息保存，但不能成为新任务的命令。

当前任务保存本episode的原始指令、目标、进度和已满足的路径约束；episode切换时重置。环境知识跨episode保留。任务要求走特定路线或依次经过地标时，也须由当前任务约束规划，不能只追求最短路径。

已知分支提供真实后果证据；陌生分支由世界模型提出未来状态假设并检索相关经历，保持unknown/不确定性。物理后果以当前状态、分支和执行策略为条件，当前指令主要决定证据关注与行动选择，不能让指令要求的物体被当成已经存在。

Harness结合当前指令、进度、当前可见分支和环境证据作决策。LightNav执行本次任务选定的局部目标。历史相似度和访问频率都不等同于本次任务的动作价值。

后果证据还必须绑定实际的局部分支、执行策略与终止条件。旧任务整段轨迹的终点，不能被当成“沿这个初始方向一定会到那里”。当前存储仍以视觉、实际方向和后果引用为主；房间/物体语义、可重组的已验证连通关系尚需完善。

## 已完成的实现修正

原live smoke使用 `revisits[0].branch_direction`直接生成左/右/前模板指令。这把环境经历当成动作建议，未体现当前任务。2026-11-05已移除这条自动接管路径。

新增 `experiments/world_model/task_planning.py`：

- `EnvironmentEvidence`：只提供真实历史观察/后果及其来源。历史方向保留在原观察坐标系，不作为当前出口候选。
- `CurrentBranch`：由当前感知工具提出，绑定当前画面、当前坐标方向和描述；不是官方节点名单，也不能仅从旧经历生成。
- `TaskPlanningContext`：把当前episode、原始指令、进度、环境证据、当前分支和各分支预测交给规划器。
- `TaskBranchDecision`：绑定当前任务标识，只能选择当前可见分支；旧episode/旧指令的缓存决策不能直接复用。
- `TaskGoalRouter`：有明确任务规划决策才设置LightNav局部目标。没有规划器或规划器弃权时，不根据环境记忆改写当前目标。

新的live默认行为是：检索并记录环境证据，保持原始episode指令，由LightNav继续生成动作。完整语义规划器、当前出口生成器和到达验证仍未实现，不能把本次接口修正称为它们已经完成。live缺少当前分支候选时不再用旧方向替代，因此不会伪造世界模型分支查询。

独立的录制前缀推理仍保留显式teacher方向的接口探针，只用于检验输入、解码与历史保留；它不是实际episode的选路器。11月4日的结果与源码快照完整保留，不按新默认行为改写旧结果。

## 目标示例

同一岔路有“左侧实际见过厨房、右侧实际见过卧室”的真实证据：

- 本episode要求去厨房，可以选左支。
- 下一episode要求去卧室，可以选右支。
- 要求先经过客厅再去厨房，应结合本次路径约束重新规划。
- 未探索的分支保留未知，用预测和主动观察获取新证据。

例子说明职责边界，不表示当前记忆已经有这些语义标签或当前模型能理解上述任务。

## 验证边界

CPU测试检查：有记忆而无规划器时不改变目标；相同环境证据支持两种任务的不同受控决策；旧任务决策拒绝用于新episode；历史方向不能冒充当前出口；没有旧经历时也可由当前任务规划器选择一个真正可见的新出口。

这些测试使用受控规划器stub，验证数据和执行边界，不是语义理解或导航成功率实验。本次没有重新训练、占用GPU或宣称新导航收益。后续应按不同目标/路线、相同场景经验预算，比较直接环境查询与未来预测检索对当前任务的帮助。
