## 结论

**这次有实质进展：图像索引和统计更可靠，六批完整旧轨迹也已补标，样本规模可以支持小模型可行性试验的准备。但新增深度监督存在明确的单位与投影错误，节点归属和拆分后的出口也未完全正确，不能把第三版所有标签直接作为正式答案。**

这次主要补的是标注和旧轨迹覆盖，没有新采图像。261 个此前检查过的原始采集元数据文件哈希未变。继续扩大补采不是当前优先事项；先修正派生标签、筛查现有样本，再根据留出场景结果决定缺什么。

## 仍需修复的问题

### P1：归一化深度直接与米制距离比较

位置：`experiments/world_model/official_nodes_entry.py:585`、`:601`。

原始 `manifest.json` 明确记录深度 `normalize_depth=true`、范围 0–10 m；实际 `.npy` 也在 0–1 之间。已有 `ego_warp.depth_to_meters` 会正确反归一化，旧路口检测也调用了它。新增 `_add_depth` 却直接把 `np.load` 得到的值传给 `depth_cone_status`，与米制目标距离比较；连有效深度的 0.05 m 门槛也因此被错用为归一化门槛。

对 go2w_04 的全部 1,637 个出口深度判断重算，**只修深度单位，保持原取样列、带宽、距离和判定规则不变，就有 1,066 个状态发生变化**：

| 深度处理 | blocked | not_blocked | unknown |
|---|---:|---:|---:|
| 当前产物 | 1,323 | 198 | 116 |
| 仅反归一化为米 | 478 | 1,159 | 0 |

这不是小幅噪声，当前深度标签暂不能用于受阻/畅通监督。修正后的数值仍是深度代理，不是可见性真值。

### P1：角度到深度像素的投影用了线性公式，距离也不在同一坐标定义下

位置：`experiments/world_model/official_nodes.py:65`；`experiments/world_model/official_nodes_entry.py:597`。

`image_column` 按角度占 HFOV 的比例线性插值。当前保存的是透视相机图像，仓库已有相机模型使用焦距和 tan：正角度向左时，应使用 `u = cx - fx * tan(offset)`。

480 像素、120° 视场中，45° 方向当前取第 60 列，透视投影约第 101 列；取样带半宽仅 8 像素。在上述 1,637 个判断中，1,358 个取样列偏差超过 8 像素，中位偏差 27、最大 44 像素。修正单位后，再只修投影，有 147 个状态继续变化。

此外，保存的深度是相机光轴 Z 距离，当前比较的是到目标的平面欧氏距离。方向偏离光轴时，这两者不一致；在上述重算上再采用目标的光轴距离，又有 49 个状态变化。最终仍需明确出口的目标区域、高度、有效深度和遮挡取样契约，不能把这些重算值直接升级为验证真值。

### P1：按导航网格拆开的节点仍继承原节点全部成员 ID 和出口

位置：`experiments/world_model/official_nodes_entry.py:530`。

`_navmesh_places` 发现一个合并节点包含不属于同一近邻区域的成员时，会生成 `#0/#1` 子节点。但它只更新 place ID、成员位置和代表位置，`viewpoint_id`、`member_viewpoint_ids`、`exits` 仍整份复制自原节点。空间上已拆开，出口答案却仍相同。

实际有 **22 个原节点拆成 45 个子节点**，上述三类字段在所有同源子节点之间都相同；17 条有图进入事件落在这些子节点上。不能保证这些子节点的出口都通向对应区域，代表 viewpoint 也可能已不在本子节点成员位置中。

建议：保留成员 ID 与坐标的一一对应，拆分后重选代表 viewpoint，基于各子节点实际成员和经过验证的连边重建出口。当前“是否为旧地点”以 place ID 为准时可以区分子节点，但后续不能改用继承的 viewpoint ID 将它们重新合并。

### P2：节点能落到网格，不代表当前轨迹已进入该节点

位置：`experiments/world_model/official_nodes.py:201`、`:508`。

新代码核验的是官方节点自身和合并成员之间的网格关系；逐帧归属仍只看平面距离和楼层差，没有检查当前轨迹位置与节点之间的短路径。

本轮用现有 Habitat Python 3.9 环境，仅加载 61 个已存在 navmesh，重现当前节点筛选并检查全部 1,670 次几何进入，没有启动 Simulator、环境 reset/step 或评测。**5 次有图进入在 1.5 m 平面范围内触发，但到匹配区域的最短网格路径分别约 35.70、29.13、8.47、8.59、5.84 m**，都位于 radius010 数据。它们与当前检查用网格的“进入”语义不一致，需核对隔墙匹配及采集/检查网格参数。

这 5 次是明确的复核标记，不是所有语义错误的估计；小于 5 m 的情况也未据此自动验收。另外，单一连通组分支保留原始成员列表，仍留有 1 个未通过 `_snap` 的成员，需要真正过滤。

## 节点语义与图像质量的边界

当前 go2w_04 的 1,840 帧中，1,566 帧（约 85%）在某个决策区域内。局部图度数、合并半径及滞回区域仍可能让长走廊/房间被大面积覆盖；需要检查时间片段，而不是看到官方 ID 就确认关键节点正确。12 张抽样联系图中可见长走廊、房间和扫描缺面，单张图无法确认所有事件是否是真正需要选择的区域。

`clearance_band` 是到最近网格障碍的距离分档，不是房间语义；`clearance_event` 是沿轨迹前后宽度变化的代理，不是经过验证的门口。它们适合辅助筛样，暂不适合作为门口/房间边界的硬真值，也不能直接把所有窄通道或开阔处都当作非节点负例。

1,604 张进入帧中有 6 张超过半幅像素近黑（RGB 三通道最大值不超过 5），需区分扫描缺面、相机挤入几何和真实暗处。文件本身能正确解码；该指标是视觉质量复核条件，不是自动证明文件损坏。

| 任务 | 当前判断 |

| 冻结 encoder，做数据管线/未来视觉表示预测试验 | 原始图像与旧完整轨迹仍可用，保持既定场景划分及代理目标定义 |

| 可见出口/受阻判断 | 当前第三版不能直接用：先修单位、投影、距离定义及拆分节点出口，然后重标 |
| 证明机器人能自主建图和识别回访 | 尚无运行时闭环证据；必须在留出场景、不输入官方 ID/邻接的条件下测试 |

建议先做一轮离线修正与重标，恢复正确几何对应；再固定少量人工核验的开发片段和失败案例，用事件召回、每米误触发、重复建点和回访误合并决定补采内容。没有必要现在再泛化地增加房屋数或帧数。
