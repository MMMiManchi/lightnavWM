## 本轮做了什么

按用户许可使用 GPU 7 跑冻结模型推理；没有训练、更新 checkpoint 或启动 Habitat。服务器原有 r2r_val_unseen_harness_20261109 八个分片继续运行，最后核对时累计 1,607 / 1,839 个 episode，均未完成。因此本轮没有再启动 Habitat 导航任务。

代码修改：

- PredictionControl 增加最低未来-历史结果余弦门槛，默认 0.5，可从 --minimum-retrieval-similarity 调整。0.5 是初始工程拒绝线，未校准。
- 预测控制只接受 outcome_kind=arrived 的历史结果。observed_span 保留为路线类比，可提供给规划器看图，但不能单独触发入口控制。
- 导航决策引用被限制到所选当前分支自己的检索结果。引用了其他分支证据时会拒绝并进行一次显式修复。
- 固定输入规划探针增加 --sample-indices，可复现地指定最多五个合法因果开发样本。

## GPU 探针与发现

产物均为新目录，没有覆盖旧结果：

- output/world_model_training/predictive_planner_probe_20261110_01：前两个因果开发样本，均只有一个当前出口。
- ..._02：按顺序扩至五个样本，仍全部只有一个出口。
- ..._03：只读扫描最多 36 个因果开发状态，在第 10、13 个检查点找到两个双出口状态（样本索引 32、35）。筛选只看当前 RGB 的候选数量，没有查看未来标签。
- ..._04：修正分支级引用后，对样本 32、35 以直接记忆、预测检索、打乱预测三种模式重跑；12 个决定成功，规划器实际调用 20 次（含修复重试）。预测检索到的历史图片确实送入规划器。

主要发现：

- 样本 32 的两个候选在预测模式下检索到相同的前三条记忆，且三种模式均选择同一候选；没有证据表明预测区分了出口或改变了决策。
- 样本 35 的首次输出存在跨分支引用，已被新校验拒绝。修复后没有跨分支引用，但部分决策返回空引用；不能据此声称预测证据导致了选路。预测和打乱模式也选了相同出口。
- 之前导航日志中两次获准的预测控制分别命中相似度约 0.673 和 0.361 的 observed_span。新门槛会拒绝 0.361 的弱匹配，但即使 0.673 也会因其是路线片段而不能直接控制。这避免把“走过一段相似路线”误作“已验证该出口通往此处”。

这些是小样本工程诊断，不是导航收益或统计泛化结论；当前任务指令和路线记忆也没有提供出口连接的真值。
