# 同场景越走越熟：与首轮冷启动训练区分

2026-11-05 更新：真实经历写回、场景残差参数梯度更新、重启恢复、当前入口几何对齐和任务进度组件已经实现并开展对照验证。最新实现、数值结果与限制见 [跨 episode 场景学习验证](world_model_online_closed_loop_20261105.md)。下文保留首轮协议与当时状态。

2026-11-04，用户再次明确：应在同一场景反复经历后，积累经验并改善未来状态预测。该目标在原事件世界模型方案第 9.2 节已有定义。首轮事件预测训练只完成了离线全局模型，尚未实现下面的持续适应实验。

## 首轮结果能说明什么

首轮不是只看一遍数据：每组 800–1300 次 batch64 更新，对 614 个训练转移而言，总抽样量相当于约 83–136 遍。这里是逆路线频率加权、有放回采样，不表示每个样本均匀出现相同次数。

模型有固定的因果视觉历史窗口，但没有跨 episode 持久场景经验库，也没有在真实后果到达后更新场景专属参数。开发场景未参与全局梯度，因此上轮评价的是冷启动的跨场景预测。

补充检查三个带分支模型的已见训练样本，场景宏平均未来特征余弦约为 0.705、0.708、0.816；开发场景平均约 0.349。前者是优化时已经见过的样本，不能当成“同场景新路线”的成绩，但说明模型能拟合部分已有经历。首轮冷启动较弱，不足以否定同场景持续适应，也不说明继续重复旧数据就能解决问题。

证据：首轮实验目录的 `exposure_and_familiarity_audit.json`。

## 正确的熟悉化闭环

```text
用当前全局参数、场景参数和已有真实经验预测
→ 执行或按真实采集顺序重放
→ 下一真实状态到达，先评价刚才的预测
→ 将真实转移加入场景记忆与回放缓冲
→ 有限更新世界模型内部的场景 adapter/LoRA
→ 在之后的回访或未用于更新的新路线评价
```

单纯增加全局训练的 epoch，与增加真实经历、持久读写记忆、更新场景参数是不同机制。预测本身不能加入真实观察索引；未走过的分支不产生真实后果标签。

## 下轮实验设计

保持冻结视觉 encoder 和全局参数 θ，以小型场景 adapter/LoRA φ_s 或预测头残差参与未来特征计算。真实后果到达后仅更新 φ_s，采用旧经历混合回放、参数版本和回滚。场景切换时按协议重置或加载对应真实经历形成的状态，不能用官方节点编号进行在线查表。

必须进行四组同条件对照：

1. 冻结全局模型，无场景持久记忆/适应。
2. 仅写入、检索以前实际经历，参数不更新。
3. 仅更新场景参数，不提供额外持久记忆检索。
4. 场景记忆与参数更新结合。

全局预训练、场景适应 support、后续 query 必须分开。每条新经历先计分再学习，query 不可参与适应或超参数选择。对实际曾走分支的回访和未走分支分别报告。目标是在增加真实先前经历后，后续预测和查询改善；不要求每一次访问都必然单调提高。

先在已有真实轨迹上按预注册顺序做离线重放，再进入实际导航闭环。离线重放不是机器人新走了一趟，也不能把重复同一组图片的记忆命中率当成新视角泛化。

## 当前数据的评价限制

首轮有效开发转移覆盖 6 个场景，其中只有 `ur6pFq6Qu1A` 有多个路线组（3 组）；另外 5 个场景各仅 1 个路线组。按排序第一路线作 support，其余路线作 query 时，该场景为 6 个 support、17 个 query，query 中只有 2 条属于 support 已见的起点/出口组合。该规模不足以给出稳健的多场景熟悉化结论。

训练侧 40 个场景中，有 32 个具备至少 3 个有效路线组，可用于重新构造内部留场景的研究协议。但现有全局模型已用过这些场景，不能直接把它们改名为“从未见过的适应测试场景”。需要重新划分全局预训练场景和适应场景，重新训练初始模型，且特征标准化统计也排除被留出的场景。原开发成绩单独保留。

建议预先登记访问顺序、适应步数预算、记忆容量、固定 query 和对照。按先前访问/经历数画曲线，报告未来特征、检索、已见/新分支、遗忘和实际新增经验覆盖；只有后续闭环才报告导航收益。

后续更新：跨 episode 持久真实记忆、检索/融合接口及因果重放已实现，见 `docs/world_model_cross_episode_history_20261104.md`。18个episode、6场景、44次转移上已验证记忆积累的初步价值；本轮固定神经参数，场景 adapter/LoRA 梯度适应仍未运行，没有把开发集并入全局训练。
