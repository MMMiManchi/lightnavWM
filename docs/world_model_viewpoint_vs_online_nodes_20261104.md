# 官方 viewpoint 与在线节点生成：Memoir 核对及方案选择

日期：2026-11-04，北京时间。范围：读取官方论文/代码、本地 connectivity 和资产目录；没有启动仿真、采集、下载图像/权重或训练，也没有改导航策略。

## 建议

用户进一步明确：**目标系统须从连续画面自主发现节点，运行时不查官方节点或邻居名单。** 官方 viewpoint 仅作为离线训练锚点、监督与可选实验上界。具体学习目标和输入隔离见 [自主节点发现方案](world_model_learned_node_discovery_20261104.md)。

**现阶段以官方 viewpoint 建立稳定的训练锚点和离散基线；连续机器人运行阶段使用在线候选节点与重定位。** 两者使用同一套“节点观察—候选分支—真实后果”接口，让世界模型与记忆系统先得到可验证的训练目标。

当前应降低继续调试自采节点聚类的优先级，先做官方锚点与现有数据的适配。官方资源可以省去大量节点定义和跨路线同一性标注工作；已经采集的 Go2 低机位数据用于连续执行、视角适配、回访与失败观察，继续保留。

“节点生成”和“从节点中选择下一步”是不同能力。官方 viewpoint 已给定节点及图结构，仍需学习指令相关的路线选择、未来状态预测和经验检索。在线自动生成节点也不必一开始从零端到端训练，可以从已有 waypoint proposer、几何规则与重定位模块起步。

## Memoir 实际怎样使用节点

核对版本：仓库 commit `ea7fb9066366eb2aff3eabbc87b227a567cc6b90`；同时读取 default main 的 README 和 `iter_env.py`，这两个文件的 blob SHA 与所核对版本一致。

1. `EnvBatch` 创建 MatterSim 并传入 connectivity 路径，启用离散视角；`getStates` 按 scan/viewpoint 取预计算观察特征。
2. `make_candidate` 在 36 个视角检查 MatterSim 返回的可导航邻居，用相同 viewpointId 合并多个方向看到的同一邻居，选角距离最近的当前观察扇区作为候选特征。候选不是从未来节点的完整图像中偷偷取得。
3. 策略的工作图随当前位置和本次观察到的邻居增量更新。环境内部有完整图，不等于策略从开始就读取全部未来观察。
4. `CollectiveGraphMap` 以稳定 viewpoint ID 组织短期图、跨 episode 图池、观察特征和历史经历。Memoir 选择检索哪些历史节点/模式，以及接下来去哪个节点；主开源路径不先训练一个从视频中发现门/岔路位置的检测器。

## 两种方案对比

| 方面 | 官方 viewpoint 作为锚点 | 在线生成、选择和重定位节点 |
|---|---|---|
| 当前训练数据质量 | ID、位置、邻接已有统一来源，跨路线容易对齐 | 依赖感知、可通行判断、去抖、节点合并和回访定位；当前代理实现误差较多 |
| 验证世界模型/记忆收益 | 容易固定节点来源，单独比较预测/检索模块 | 节点误检、错合并、执行失败与世界模型误差耦合 |
| 工程工作量 | 主要是资产准备、视角/坐标适配与连续可达性检查 | 还需要可靠的候选提议与图维护，学习版另需监督和泛化验证 |
| 事件语义 | viewpoint 是几何采样点，不自动等于门口、岔路或指令事件 | 可以围绕实际决策位置和任务相关地标设置，前提是识别可靠 |
| 陌生真实环境 | 没有数据集提供的 ID 和连通图，必须由建图/重定位补足 | 更符合真实部署所需的输入能力 |
| 本项目建议 | **现在优先用于训练标签、稳定锚点和基线** | **作为连续闭环中的部署能力分阶段引入** |

当前最值得先回答的是“世界模型预测是否确实改善记忆检索和分支选择”。先固定节点来源有助于回答这个问题；节点生成模块可靠后，再研究自适应选点的收益。

## 官方节点省掉什么，还剩什么

可以省去或显著简化：从少量自采轨迹猜节点位置、用距离聚类猜同一地点、给跨路线重访人工建立相同 ID，以及从不完整行走推测基础图结构。

仍需完成：

- **观察准备。** 使用官方全景/兼容特征，或在投影后的锚点取得本项目相机观察。原始 panorama 及其特征不等于 Go2 相机 0.50 m 高、120° HFOV 的图像；视角适配需要单独验证。
- **连续可达性。** connectivity pose 是 Matterport Z-up 相机坐标，height 是距地估计，不是 Habitat 地面 agent pose。邻接也是离散图的可导航标注，不保证当前 agent 实际走通。VLN-CE 原论文已经专门处理相机高度、家具与 mesh 差异造成的投影/路径失效。[官方格式](https://github.com/peteanderson80/Matterport3DSimulator/blob/master/connectivity/README.md)、[VLN-CE §3](https://www.ecva.net/papers/eccv_2020/papers_ECCV/papers/123730103.pdf)
- **经验与时间。** 执行前只能访问已允许、已发生的观察与经历；官方图的存在不允许把未观察的目标节点 RGB 提前放入实际记忆查询。全图已知的离散基线/上界与 RGB 连续导航分别报告。
- **执行与失败数据。** 官方 A→B 图边可以监督离散下一状态预测；Go2 的绕障、受阻、控制器偏差、到达条件及回溯仍需要连续执行证据，现有采集可用于这层适配。

学习节点生成也不会自动解决这些问题，它主要改变候选及锚点来源。

## 推荐接入方式

训练侧用 `canonical_viewpoint_id` 对齐同一物理锚点，构造当前观察、候选方向/技能和后续真实观察的监督。先保留所有 included viewpoint，不用度数或固定间隔直接伪造语义事件真值；事件语义另设标签/未知字段。

运行侧让节点提议、视觉重定位和历史连续性形成自己的 `online_node_id`。训练时官方 ID 可以做标签与对照，世界模型主要消费视觉/历史和可部署的相对候选描述，避免只记住训练场景 ID。

预测、记忆与 Harness 均通过同一节点接口工作，节点来源记录为 `official_anchor` 或 `online_proposal`。官方锚点可以在训练和实验上界中使用，部署时替换节点生成接口。

建议的对照是：固定官方锚点时比较无世界模型/有世界模型；连续环境里再比较 oracle 锚点与在线候选，并单独报告定位、到达和执行误差。传感器与控制器保持一致，区分给定图的辅助与模型本身的收益。

## 下一步唯一任务

**先建立 viewpoint→Habitat→真实观察的适配清单和小样例。** 交付包括 source viewpoint ID、源坐标、经验证的地面锚点、真实 RGB 引用、候选邻居、当前 agent 的可达性状态以及训练/开发划分。无法投影、缺图、跨楼层不确定或没有执行证据的部分保持 unknown。

在这个适配清单确认后，再确定采用官方全景特征预训练，还是优先补齐 Go2 同锚点观察。当前不继续扩张未经核验的自采节点聚类；不丢弃已有轨迹和失败样本。
