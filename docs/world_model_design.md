# LightNav-0 轻量潜在世界模型设计

日期：2026-10-23。最终研究目标是：

**轻量潜在世界模型 → 用预测的未来状态作为查询 → 从当前 episode 的空间记忆中检索相关历史 → 把检索结果接入 LightNav 导航决策。**

这借用预测引导记忆的想法。它不移植 DUET、Matterport3DSimulator 或离散视点图。v1 只做到可检验的单步潜在预测和局部位姿预测。它不接入导航，因此不能声称 SR、SPL、NE 或 nDTW 发生变化。单步位姿回归也不是完整的世界模型导航方法。

## 1. 已核实的现有链路

导航策略的在线输入是 RGB 历史和指令。`TrajVocabVLNCEPolicy.act` 调用 `generate_from_frames`，返回值只有文本和延迟。三个 RVQ token 解码成一条 10 点局部轨迹，控制器只提交第一个可用航点对应的速度命令。服务端可以在底层 step 之前替换动作。depth 存在于 Go2-W 传感器配置中，策略不读取它。

`generate_from_frames` 内部会做多帧 ViT 和 slowfast 池化。那些 `video_embeds` 没有写入 transition，也没有按原始帧和时间戳导出。一条嵌入可能混合多帧。在单独完成逐帧对齐审计之前，v1 不复用 LightNav 视觉特征，也不微调 LightNav，不改 checkpoint，不改评测指标。

## 2. v1 预测什么

冻结编码器 `E` 将 RGB 变成向量。v1 的默认实现还没有选定本地权重。测试里用固定随机种子的残差网络和拷贝基线检查接口，不用试点图像训练。

```text
z_t  = stopgrad(E(rgb_t))
z_t1 = stopgrad(E(rgb_t1))
u_t  = (v_mps, w_rad_s, dt_command_s)   # 来自 final_habitat_action
z_hat_t1, delta_pose_hat = F(z_t, u_t)
```

`F` 是 `ResidualLatentPredictor`：小型 MLP，输出加回 `z_t`，所以零初始化时视觉头等于“保持当前特征”。第二个头输出 `(forward_m, left_m, delta_yaw_rad)`。指令文本随样本保存，v1 的 `F` 不接收语言向量。以后若加入语言，必须使用冻结编码器并单独报告去掉语言后的差别。

位姿监督来自特权位姿的机体增量，定义见数据契约。碰撞、受阻、进展和 STOP 头都不进入 v1：碰撞标签是 `unknown`，进展要用测地距离，而本运行没有一条 `model_stop=true`。这些头只有在标签本身是测量结果时才增加。

## 3. 损失

三项分开计算，模块内部不相加：

| 项 | 定义 | 单位 |
|---|---|---|
| `latent_mse` | `z_hat_t1` 与 `z_t1` 的均方误差 | 编码器输出的平方 |
| `translation_huber` | 前向和横向的 Smooth L1 | 米 |
| `yaw_cosine` | `mean(1 - cos(yaw_hat - yaw_true))` | 无量纲，周期为 2π |

权重由后续正式实验在 `train_fit` 上选定，并写进配置。不得用一个未加权的标量和来宣称两个任务同时变好。

## 4. 三种基线

**A. 持续状态。** `z_hat_t1 = z_t`。只在两个向量来自同一个冻结编码器、形状相同且都有限时比较。报告 MSE 和余弦距离。零向量的余弦距离记 null，不改成 0。

**B. 运动学。** 只根据已提交命令预测局部位姿，不预测视觉特征，因此不能与 A 的潜在状态 MSE 放在同一个比较里。反归一化后，低于 Habitat 停止阈值则增量为 0；否则 `forward = v * dt_command_s`，`left = 0`，`yaw = w * dt_command_s`。这里的 `dt_command_s=0.1` 是命令时间步长，不是经过验证的模拟器实际时间。B 是基于命令时间步长的近似积分，不是物理轨迹的精确预测。它不包含 `integrate_transform` 和 navmesh 滑动。在已验收的 60 条上，航向误差小于 `1e-5` rad。前向残差平均约 `1.1e-3` m，最大 `4.6e-2` m。在确认 navmesh 滑动、速度裁剪、碰撞或位姿测量误差之前，不把该残差归因于其中任何一种。

**C. 学习模型。** 第 2 节的 `F`。视觉指标与 A 比，位姿指标与 B 比。改善量是基线误差减模型误差。只在场景和路线组都达到第 5 节的下限之后，才把这个改善当作验证结果。

## 5. 数据划分

采集器 `wm-group/0.1` 按 `route_group_id` 的 SHA-256 末字节划分，末字节模 10 等于 0 的为 `train_dev`。同一场景的不同路线可以落在两侧。视觉预测若沿用它，会出现场景泄漏。

世界模型使用预注册规则 `wm-scene-split/0.1`：对 **scene id** 做同一哈希，一个场景的全部路线和指令都继承该场景的一侧。不按帧、不按相邻 step 划分。这条规则不回写已采集的 `partition` 字段。

正式训练和正式验证同时要求：

| 集合 | 场景数 | 路线组数 |
|---|---|---|
| `train_fit` | 至少 8 | 至少 20 |
| `train_dev` | 至少 3 | 至少 5 |

两侧的场景集合和路线组集合都必须不相交。任一条 episode 的 `source_split` 必须是 `train`。达不到下限时 `require_formal_split` 抛出 `FormalSplitError`，不得改成随机逐帧划分。

已验收试点的两个场景 `7y3sRwLe3Va` 和 `5LpN3gDmAk7` 在场景哈希下都是 `train_fit`。`train_dev` 场景数为 0。两条 `7y3sRwLe3Va` episode 同属路线组 `7y3sRwLe3Va:4`。因此该运行只能检查接口，不能做正式验证，也不能事后把其中一个场景划成验证集。

`val_seen`、`val_unseen` 和 `test` 不参与训练、归一化统计或模型选择。导航闭环以后的最终测试还要另留未见场景。

seed 状态是 `partial`。报告可以记录请求值 7、配置写入、`Env.seed` 已调用，以及没有模拟器回读。不能写成完全确定性。GPU 确定性未声称。

## 6. 评估报告里要有的量

按场景和路线组汇总，而不是只报一个训练集 loss：

- 潜在 MSE 和余弦距离，以及相对基线 A 的差
- 平移误差（米）和 wrap 后的航向误差（弧度与度），以及相对基线 B 的差
- 按场景、`action_kind`（`stop_threshold`、`turning`、`mostly_forward`）、`quality` 分组的误差
- 样本数、fit/dev 的场景数和路线组数、随机种子、配置、checkpoint 路径、Git commit、dirty diff 哈希
- 缺失观测、终止帧、预算截断、`model_stop`、服务端替换和异常 step 的计数

`action_kind` 使用命令产生的航向步长，阈值是 0.05 rad。本试点的 60 条是 36、21、3。这是描述统计，不是模型效果。

## 7. 以后怎样接入记忆

v1 不实现检索，也不改 LightNav 的样本构造。后续阶段的顺序是：

1. 记忆只保存当前 episode 里、当前决策之前已经观测到的条目。reset 清空。条目可以含视觉特征、相对位姿、已执行动作、当时的指令上下文和预测误差。不含目标点和测地距离。
2. 查询向量来自 `z_hat_t1`。对照查询来自 `z_t`、最近帧和随机历史。离线评分可以使用真实 `z_t1` 作为 oracle 查询，但在线决策不能读取它。
3. 比较“用当前帧检索”和“用预测未来状态检索”。指标是 Recall@k、MRR，以及检索到的历史是否更接近未来观测。视觉相似不等于导航帮助，这个区别要单独写。
4. 检索到的过去 RGB 若要影响导航，必须经过一个可关闭的适配层进入现有视频历史，并受 token 预算约束。当前 `generate_from_frames` 没有检索索引参数。只写一个检索分数日志不算接入决策。
5. 闭环实验在冻结的 LightNav 上比较适配层开与关。那时才可以报告 SR/SPL/NE/nDTW。服务端原有的 early-stop 保持原样并披露，不把它当作新策略的输入。

## 8. 尚未解决

- 没有选定并核验本地冻结视觉编码器。未下载新权重。
- LightNav 逐帧视觉特征与原始帧的对齐仍待验证，所以没有复用。
- 平移残差里有多大比例来自 navmesh 滑动或碰撞，待验证。碰撞传感器没有读到。
- 模拟时间没有接口。
- 单次 reset 的 seed 没有传到 `BaseHabitatEnv.reset`。
- 语言特征是否改善单步预测，待有正式划分后再测。
- 本试点没有模型 STOP 的正样本，停止预测头没有监督。
