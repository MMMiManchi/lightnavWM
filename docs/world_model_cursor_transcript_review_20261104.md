# Cursor 最近对话与数据制作审查

审查日期：2026-11-04。范围是 LightNav 项目 11 月 3 日补采至 11 月 4 日官方 viewpoint 重标的对话、当前代码及已落盘产物。没有修改 Cursor 的采集/标注实现和原始数据，没有启动仿真、提特征或训练。

## 结论

Cursor 已理解“官方节点只作离线教师，运行时从连续图像自主发现节点”的目标，也已完成两批房屋探针和一版官方节点标注。**当前落地的是几何规则生成的弱标注，尚不能当成验收合格的自主节点发现训练集。** 主要问题是教师图断环、位置记录被计作图像帧、分支前缀共享对象导致 ID 冲突，以及出口可见性未经真实相机位置和遮挡核验。

不需要把所有原始数据作废或立即扩大补采。先修正离线标注和图像对应关系，再利用现有完整轨迹整理样本，最后按独立场景的结果决定补采。

## 从最近对话还原的过程

1. **从深度图提候选路口。** `decision_nodes.py` 在图像地平线附近取深度带，以开阔方向和间隔规则识别出口；同一小区域的多帧聚类为节点。它不是训练出来的语义节点发现器。
2. **回放后尝试未走出口。** `branch_exit_entry.py` 回放原正式轨迹的动作，先核对位置/朝向，再转向未走出口，用深度和身体高度通行条件控制行走。曾经出现视线越过椅子、身体撞上椅子的情况，Cursor 后来增加了身体高度检查和同侧绕行。
3. **补采房屋探针。** 两批覆盖 45 个场景，每栋先找候选路口，再尝试至多两个出口，总预算采用 500 步。搜索途中主要保存位置和朝向，搜索起点/找到的节点保存 RGB-D，出口尝试期间逐步保存 RGB-D。采集并非沿官方节点清单逐点遍历。
4. **整理场景图并人工看俯视图。** Cursor 做过近邻合并和交汇点调整，但“点落在路线附近”不能独自证明节点、出口和后果都有效。旧版图像缺失、到达规则等问题见此前数据审计。
5. **11 月 4 日改用官方 viewpoint 作教师。** 当前 `official_nodes.py` 将坐标转到 Habitat，按规则筛分岔/转弯，近处分岔合并；轨迹进入 1.5 m 区域算进入，超过 2 m 才离开，用官方 ID 相同生成回访标签。结果写在 `official_nodes_20261104_01`，不是写回原始轨迹，也没有开始训练。

用户在对话第 3678 行明确授权继续采集、检查和修正，所以后续补采本身在授权范围内。第 3579/3592 行明确要求保留回环；第 3735 行明确要求连续图像、进入时机、可见出口和回访。这些要求是本次检查的依据。

## 已确认问题

### P1：先取生成树，教师图中的所有环都被断开

位置：`experiments/world_model/official_nodes.py:71`，`_spanning_tree` 在第 174 行开始。

当前流程在判断分岔/转弯和生成出口之前，对同层官方连通图执行 Kruskal 生成森林。某条边只要闭合一个环就被删除，随后节点度数、有效支路和出口全部基于这个树计算。它会把真实回环中的通路当成不存在，从而漏标节点、减少出口，并把相应画面留成背景。

实际输出涉及的 60 个场景：同层图有 15,638 条边，生成树保留 7,548 条，删去 8,090 条闭环边。官方扫描图有冗余可视连边，**这不表示删掉的 8,090 条全是独立物理通路**；问题是算法没有区分冗余连边与真实环路，一律断环。四个角、边长 4 m 的方形走廊复现中，四个明显转角只保留两个。

建议：按空间区域、出口方向和机器人通行几何消除冗余；保留真实回环，分别记录完整教师连通关系和经过筛选的决策区域。不要以生成树的度数作为真实分岔答案。

### P1：搜索位置记录被计为训练图像，159 次进入不是 159 个可用视觉样本

位置：`experiments/world_model/fit_house_entry.py:136`、`:189`；`experiments/world_model/official_nodes_entry.py:220`、`:225`。

搜索过程的 `path.jsonl` 仅保存位置和朝向。新标注脚本把这些记录与分支图像拼在一起，统一写成 `frames.jsonl`，没有保留可核验的 RGB 路径，也没有区分“只有位姿”和“真实观察”。

本次按原始记录逐条还原了来源，以真实文件存在和原始 RGB 哈希计算：

| 训练侧项目 | 报告/记录数 | 有对应 RGB 的记录 | 不同 RGB 图像数 |
|---|---:|---:|---:|
| 全部标注帧 | 17,027 | 7,394 | 6,867 |
| 进入事件 | 159 | 113 | 105 |
| 同一条轨迹重访事件 | 13 | 5 | 5 |
| 先前其他轨迹已进入的地点 | 43 | 27 | 27 |
| 报告至少有一个可见出口的进入事件 | 121 | 88 | 80 |

训练侧 9,633 条“帧”和 46 次进入只有搜索位姿，没有对应的已保存图像。113 条有图的进入记录涉及 84 个地点；若要求进入时刻及之前连续 5 帧都有 RGB，只有 73 条满足。这个 5 帧窗口只是可恢复性检查，不是建议的固定模型长度。

13 次同轨迹重访中，仅 3 次的当前进入和此前进入都保存了进入帧图像；这不是所有可构造重访图像对的上限，因为还可能从区域内部其他帧建立记忆，但不能把 13 直接当成 13 组完整视觉回访正例。

已引用的 RGB 文件均存在，问题不是磁盘上图像文件损坏，而是搜索中间帧从未按该观察记录保存。新探针图像的解码/文件哈希全检结果见此前数据审计。

建议：独立记录 `has_rgb`、真实观察 ID、图像路径/哈希和时间；位姿轨迹只能用于离线几何检查。无法恢复 RGB 的位置不能塞进连续视觉训练窗口。Cursor 第 3792 行所说“159 次够训练这个小网络”缺少依据；数量应以去重后的完整视觉片段和独立场景学习曲线判断。

### P1：两条分支共享搜索字典，后一个分支会改掉前一个的观察 ID

位置：`experiments/world_model/official_nodes_entry.py:225`、`:236`。

`[*search, *tail]` 只复制列表，搜索前缀里的字典仍被两个分支共享。随后原地写 `frame['observation_id']`，第二个出口会重写第一个出口的前缀 ID。

实际产物存在 2,582 个重复观察 ID，每个多出一次记录；同样有 2,582 条记录的 ID 出口前缀与所属 `episode_uid` 不一致。进入表有 24 个重复 ID、24 条前缀不一致记录。按观察 ID 建索引会覆盖或错误关联；共享前缀也会夸大事件数，按分支随机拆训练/验证还可能把同一路径重复分到两边。目前按场景划分没有发现 fit/dev 混入。

建议：采集阶段生成不可变的原始观察 ID。共享前缀保留同一原始 ID，分支经历另有唯一 occurrence ID；如需修改帧对象则复制字典。不能只换一个字符串，把重复前缀当成两次新的实际采集。

### P1：当前 `visible_exit_ids` 不是可见性真值

位置：`experiments/world_model/official_nodes.py:50`、`:125`。

实现只判断“从官方节点中心算出的固定出口朝向”是否落在当前 yaw 的 ±60° 内，没有使用当前帧的位置或深度遮挡。轨迹在 1.5–2 m 的区域内移动时，出口相对相机的方位可以明显变化；隔着墙、门框或家具，也可能仍被标为可见。

无需遮挡即可复现：出口在节点中心视角偏左 55°，机器人向右移 1.4 m 后，该出口方向约偏左 66°，已经超过 120° 视场，但代码仍标为可见。改成从真实相机位置朝对应相邻 viewpoint 发射角度射线后，有图的 113 次进入中，80 次的角度集合与现标注不同。**相邻 viewpoint 射线本身也只是代理，不能把这 80 次直接宣称为真实可见性错误率。** 它说明该标签依赖被忽略的位置，不能当作已核验的图像出口答案。

建议：从当前相机位姿投影经过验证的出口区域，结合深度、遮挡和通行几何检查；证据不足记 unknown。仅完成方向角检查时字段应明确叫角度候选，而非真实可见。

## 还未完成的部分与覆盖范围

- **进入时机仍是半径规则。** 159 次进入中 37 次发生在记录的第 0 帧，缺少此前“在区域外”的观察，不能直接作为“刚进入”的正例；需要单独定义启动时已在区域内的状态。接近/进入/离开及重复触发应以连续片段监督。
- **官方点没有验证机器人可达。** 当前只是坐标换轴并减相机高度；绘图加载 navmesh 不等于标注使用 navmesh。最近点和区域归属仅用平面距离及楼层差，无法排除隔墙或不可达的邻近区域。门口、房间交界和邻近不同地点的区分也没有验收。
- **新脚本没有覆盖全部已采正式数据。** `event_spans_entry.SPLITS` 只列 `formal_fit_20261028_04` 和 dev，遗漏六批 radius010 正式采集，共 48,729 条 transition；独立 `branch_exit` 探针也未合入。radius010 的机器人半径配置有差异，不能无条件混入，但应明确兼容性和筛选标准，不能据这版 159 次进入推断全部存量只有这么多监督。
- **回访目前仍是教师 ID 相等。** 适合生成监督线索，尚未验证换朝向识别、相邻地点分离、自主节点创建、证据不足再观察等运行时行为。
- **重标产物缺少版本证据。** 对话第 3775 行有删除并重建同一 `official_nodes_20261104_01` 目录的记录，未见源文件哈希和版本化标签协议；后续应保留独立版本及输入清单，避免看到的统计与代码/标签版本不同。

Cursor 最后一条回复（第 3801 行）已明确承认门口、房间交界、navmesh、接近/离开和自主回访等尚未完成。这部分披露是准确的；此前“按这个标准标好了”“159 次够训练”的表述则超出了当前数据证据。

## 建议的处理顺序

1. 保留现有原始 RGB-D、执行轨迹和失败/截尾记录；暂停把这版标签当成正式答案。
2. 修正保环的教师图、不可变观察 ID 和 RGB 对应；只输出有真实图像的视觉训练片段，缺失和未知单独记录。
3. 核验官方锚点到机器人 navmesh 的位置及通路；用实际相机位姿、图像/深度生成可见出口弱标注，区分 unknown。
4. 在可兼容的完整正式轨迹上统一补标，明确冷启动、接近/进入/离开、区域内重复帧、同地点重访和相邻不同地点。先利用存量，不直接扩大补采。
5. 冻结视觉编码器，以小型时序发现器做可行性试训；按场景固定划分，评估事件召回、每米误触发、重复建点、回访识别及相邻节点误合并。用结果决定需要补采的具体情况。
