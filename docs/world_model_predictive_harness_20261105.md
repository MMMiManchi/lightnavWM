# 预测查询接入当前任务规划

日期：2026-11-05（北京时间）。这是环境记忆与当前任务分离之后的实际接入，旧训练、数据和11月4日实验结果不改写。

后续已用8卡完成多场景经验预算回放与48次导航，见 [场景熟悉度实验](world_model_scene_familiarity_20261105.md)。下文保留首次接入的实验结果。

## 接入方式

```text
当前RGB → 冻结SigLIP：实际观察特征、当前图像列特征
       → 独立Qwen视觉工具：当前可见的下一入口候选
每个当前入口 + 实际视觉历史 + 严格过去episode经历
       → 已训练的v3模型：1152维未来查询特征 / 无历史支持时弃权
       → 用未来查询与记忆中的实际后果特征做余弦检索
       → 返回过去真实源画面、实际后果画面及经历编号
当前指令 + 当前入口 + 检索图像 + 执行反馈
       → Qwen任务规划：选择当前入口 / 请求观察 / 保持原指令
       → 校验任务标识、候选来源、经历可见时间
       → LightNav执行当前局部指令，保留本episode原生完整时序历史
```

LightNav仍加载原始 `checkpoints/LightNav-0`。独立通用视觉工具使用 [Qwen/Qwen3-VL-4B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct)，固定revision `ebb281ec70b05090aa6165b016eac8ec08e71b17`，本地文件和权重SHA-256逐项校验；不修改LightNav权重，也不把LightNav动作头当成通用问答模型。规划器贪心解码，真实CUDA推理。

本地规划器资产位于 `checkpoints/world_model_planner/Qwen3-VL-4B-Instruct/`。固定文件清单随代码保存在 `experiments/world_model/contracts/qwen3_vl_4b_instruct_assets.json`；另一个环境可用以下命令准备同一版本，再运行逐项SHA校验：

```bash
hf download Qwen/Qwen3-VL-4B-Instruct --revision ebb281ec70b05090aa6165b016eac8ec08e71b17 --local-dir checkpoints/world_model_planner/Qwen3-VL-4B-Instruct
cp experiments/world_model/contracts/qwen3_vl_4b_instruct_assets.json checkpoints/world_model_planner/Qwen3-VL-4B-Instruct/asset_manifest.json
```

当前世界模型权重仍是内部验证选择的 `event_anchored_v3_20261104_01/anchored_gate_only_seed20261104/model.pt`。本次没有重新训练。它学习历史后果的读取和混合，陌生分支仍不能有效独立预测。无匹配历史时复制当前特征的数值退化，被查询服务标记为无支持，不以此检索“预测未来”。

## 查询接口与实现位置

`experiments/world_model/predictive_queries.py` 中的 `BranchQueryService` 是进程内查询接口。每个episode持有一个服务实例，固定可见经历截止序号；预测不会写回真实记忆。

输入：当前任务指令、当前观察引用、当前RGB提出的候选（当前相机方向与图像框）、8个实际历史视觉特征及有效mask、当前27列视觉特征。特征编码/标准化必须与训练权重、记忆库合同一致。

输出：绑定本episode和原始指令的 `TaskPlanningContext`。其 `predicted_branches` 对每个当前候选返回未来向量、历史支持标记、模型预读经历编号、检索到的实际经历及时间截止。`last_trace` 保存查询向量哈希和检索来源，支持逐步追踪。

```python
context = queries.build_context(
    instruction=original_instruction,
    source_observation=current_observation,
    branches=current_rgb_branches,
    raw_history=actual_history_features,
    valid=actual_history_mask,
    columns=current_image_columns,
    progress=execution_feedback,
)
local_goal = task_router.consider(context)
```

未来向量用于检索键匹配，不直接塞给语言模型。`scene_memory.py::query_actual_outcomes` 按预测与真实过去后果的余弦排序，检索范围受场景记忆命名空间、过去时间和episode排除约束；当前源画面相似度与旧方向只返回作审计，不是这一轮后果键搜索的过滤条件。世界模型预测前的记忆预读仍使用源画面/方向匹配。这是两个不同阶段。

`visual_harness.py` 把每分支首条检索经历的真实源图与后果图送入任务规划器，校验原始图像文件SHA；所有候选仍保留查询的最多3条结果用于审计。图像是历史证据或类比，不能当成当前分支的已验证连接。旧任务指令不作为选路输入，旧方向保留在旧相机坐标系，当前朝向对齐尚未验证。

`predictive_harness.py` 组织实际观察、少量当前episode历史决策画面、逐分支查询及任务路由。历史锚点是实际发生的规划时刻，不等于已验证拓扑节点。`task_planning.py` 校验当前任务标识、当前分支与可见经历，禁止旧任务缓存决策或历史方向冒充当前入口。

`scripts/smoke_event_lightnav.py --planner-model ...` 运行真实三模型链路。未提供规划器时仍由LightNav执行原始episode指令。仅提供显式teacher方向的录制前缀探针单独保留，不能当成实际选路实验。

## 对照与质量边界

`scripts/probe_predictive_planner.py` 固定相同当前图像、候选和过去经历预算，比较 `direct`（直接历史查询）、`predicted`（未来键查询）、`shuffled`（在候选间循环置换未来向量）。规划器不看到对照模式名称。测试两条当前目标指令；样本取有因果历史的开发查询中按采集顺序最早的两项，不按模型效果挑选。它们来自同一场景、同一episode的两个时刻，并非跨场景泛化证据。

第一轮实际测试在 `output/world_model_training/predictive_query_probe_20261105_01/`：完成14次真实VLM调用（2次候选提出、12次规划）。预测检索确实改变了所读取的经历，但两个候选的首条后果经常相同，打乱预测没有提供决策改善证据。复核还发现同一入口的嵌套框被当成不同分支，规划理由把一般家具误认作床。不能据此宣称可靠的语义规划。

随后增加下一入口限制、重叠/包含框合并、枚举校验和目标物体不确定性提示，保留第一轮结果，使用相同样本复跑。提示约束本身不证明物体识别可靠。

第二轮 `predictive_query_probe_20261105_02/` 同样完成14次VLM调用、12次通过校验的规划；两个时刻都剩1个当前入口，预测条件共有4次有历史支持的查询（同一候选被两条任务分别查询）。检索图像确实送入规划器，但它仍会把无床的历史图像说成有床。单入口使shuffled对照成为恒等置换，不能用这轮判断分支排序收益。随后扩到按采集顺序最早五项，协议保持固定；没有按成功挑选。

首轮55步仿真 `predictive_harness_live_20261105_01/` 发现规划器混淆图像索引和经历编号：7次规划中6次引用未提供的编号0，被校验拒绝，未提交局部目标。最终距目标2.303米、success=0。该轮拒绝时未保存完整查询中间状态，结果中的查询计数不完整，不能解释为模型没有执行查询。后续修复明确允许编号集合，最多一次带校验错误反馈的模型重答；保留拒绝，不静默删除引用。增加每次规划当前RGB、完整查询/原始响应及逐步动作落盘，再同场景同预算复测。

## 本次验证

最终扩样结果位于 `output/world_model_training/predictive_query_probe_20261105_04/`。中间编号03在实验初始化前被外部源码快照写入目录，触发“拒绝覆盖”的保护而未运行，保留失败目录，使用新编号重跑同一协议。

- 固定样本23–27，来自同一场景的episode20、21、43；每个时刻只有1个保留下来的当前入口，尚未覆盖真实多分支比较。
- 完成35次真实VLM调用（5次入口提出、30次任务规划），30次规划均通过接口/引用校验。这是有效JSON与来源约束通过，不代表语义判断正确。
- 10次预测条件查询均有历史支持；5个不同图像查询被两条任务分别调用。过去经历数依次为2、2、4、4、6。
- 相比直接历史检索，两个不同当前画面的首条后果发生变化，对应4个任务条件。实际源/后果图像确实被送入规划器，而不是只记录预测向量。
- 因所有样本均为单入口，shuffled是恒等置换；不能判断预测能否改善分支排序。样本25的不同任务触发不同操作，但也不能据此证明目标语义识别可靠。
- 因果审计核对74条检索结果：均对应严格更早episode的真实记录，给规划器的图像引用与该记录相符。世界模型、规划器资产与源码快照校验通过。

修复后的真实三模型仿真结果位于 `output/world_model_training/predictive_harness_live_20261105_02/`：

| 项目 | 结果 |
|---|---|
| 环境与预算 | 同一已知场景、episode20，最多55步 |
| 规划 | 7轮，0次接口错误，3次局部目标提交 |
| 实际执行 | 55步均返回新RGB；局部目标下执行24步 |
| 当前分支请求 | 5次；0次通过历史源/方向匹配，没有实际后果图像可供这些预测请求读取 |
| 任务终点 | 距目标2.366米，success=0、SPL=0；达到客户端预算后关闭，不能当成成功STOP |
| 主动观察/局部STOP | 本轮均未触发，不能把已实现接口当成这轮验证过的能力 |

该轮确实接通视觉候选、未来请求、任务规划和LightNav执行；但世界模型均弃权，局部目标根据当前任务和画面提出，不能说预测记忆改善了这一轮导航。前一轮退回原始指令时距目标2.303米，两轮均未判成功，不是正式导航对照评测。

弃权复核 `query_abstention_review.json` 显示：第40步已经有源画面相似度0.747的旧经历，第48步最高0.860，但当前入口方向与旧相机坐标中的分支方向相差约60–98度，超过35度预读限制。当前视角未对齐，训练分支也来自离线几何出口选择，而live使用当前入口图像框；不能简单放宽角度门限就把它们认作相同连接。下一步应优先解决当前入口与历史分支的对应和相机朝向对齐，再做多出口、不同当前任务的导航对照。

相关CPU测试：世界模型/记忆/路由56项、原生SlowFast/速度/策略75项，共131项通过；相关文件Ruff通过。无 `src/lightnav/` 改动，无新训练、无原始数据或训练权重改写。实验结束后8张GPU均释放。

## 尚未完成

- 可见入口来自通用VLM提出，没有深度通行验证；周期性规划也不等于自主识别决策节点。
- 没有可靠的局部到达验证器、完整的指令阶段跟踪、独立回溯策略和最终STOP判别器。局部STOP只能报告“未验证”，不能当成已到达。
- 本次live只读取严格过去episode的真实经历，不把预测或尚未验证到达的执行写成新经历。因此尚未跑通自行写入、跨episode越走越熟的完整闭环。
- 场景记忆命名空间由实验启动配置提供；尚未实现未知场景识别、相机朝向对齐或已验证拓扑连接。
- 当前模型是历史支持下的后果特征校准器；陌生分支保留未知。预测收益要在相同经验预算、多任务、多场景导航对照中验证，本次接通不等于导航成功率提升。
